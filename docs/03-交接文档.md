## 五、架构速览（详见 01-架构设计.md）

- 分层：`Core（抽象）← Drivers（实现）← App（WPF）`，`Simulator（自研模拟器）`，`Vision`
- 两大核心抽象：`IDeviceDriver`（采集驱动插件）、`IMotionControl`（运动卡插件）——**模拟实现先行，真卡/真协议只换实现**
- 三套坐标系：相机像素系 ↔ 机台世界系（九点标定仿射变换）↔ 画布显示系；相机视场中心已对准机台原点（WorldOrigin -32/-24）
- 视觉构型：**Eye-to-Hand（固定相机）**——轴动工件不动是正确行为

## 六、排坑记录（面试素材，全有提交记录背书）

1. snap7 Server API 区域编号是内部值 **DB=5**，不是协议层 0x84
2. snap7 导出函数名是 **Srv_Destroy** 不是 Srv_Delete（反查 DLL 导出表定位）
3. **FC16 响应的 MBAP 长度字段必须按响应重算**——沿用请求头会让主站无限等缺字节（通讯假死的经典成因）
4. NModbus 传输层默认无限读超时 → 补 2 秒超时防采集线程挂起
5. Serilog 10 的 UseSerilog 不支持 HostApplicationBuilder → 日志保持静态初始化
6. Windows 运行中的 exe 锁输出 DLL → 构建前关进程
7. 切换设备时残留点位行：新旧设备同名点位在行字典互相顶替 → 连接前 Clear
8. 相机视场 WorldOrigin 与机台原点不对齐会让"引导到位"看起来像"偏移"
