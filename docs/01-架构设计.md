# 01 架构设计

## 分层与项目

```
┌──────────────────────────────────────────────┐
│  DeviceHub.App (WPF/MVVM)                    │  组装根：Generic Host + DI；五页签+登录
├──────────────────────────────────────────────┤
│  DeviceHub.Northbound      北向：OPC UA Server / MQTT 发布（托管服务）          │
│  DeviceHub.Storage         SQLite 历史存储 / 后台批量写 / Excel 导出           │
│  DeviceHub.Vision.Halcon   视觉第二引擎：形状匹配定位器（IVisionLocator 实现）  │
├──────────────────────────────────────────────┤
│  DeviceHub.Drivers         南向驱动：Simulated / S7 / Modbus TCP+RTU          │
│  DeviceHub.Vision          合成相机 + 轮廓定位器（OpenCvSharp）+ 九点标定      │
│  DeviceHub.Simulator       自研 S7 从站 + 迷你 Modbus TCP 从站（测试用）      │
├──────────────────────────────────────────────┤
│  DeviceHub.Core            抽象与模型：IDeviceDriver / 采集引擎 / IMotionControl │
│                            IVisionLocator / 报警引擎 / TrendBuffer / 存储·导出·北向接口 │
└──────────────────────────────────────────────┘
     依赖方向：上层依赖下层，Core 不引用任何上层项目（Tests 引用全部）
```

依赖倒置是本项目的主线：**驱动是插件，引擎和界面是宿主**。
新增南向协议 = Drivers 里新增一个 IDeviceDriver 实现；换视觉引擎 = IVisionLocator 换实现；
加北向通道 = Northbound 里加一个采集流消费者——Core 与既有代码零改动。
存储与导出同理（IPointHistoryStore / IHistoryExporter）：SQLite、Excel 都只是接口的当前实现。

## 核心抽象：IDeviceDriver

- `ConnectAsync / DisconnectAsync`：连接生命周期
- `ReadAsync(点位表)`：批量读取，返回与请求一一对应的结果，读不到给 Bad 质量
- `WriteAsync(点位, 值)`：下行控制

设计取舍：
1. **批量读而不是单点读**——真实 PLC 通信一次握手读一段寄存器远快于逐点读，接口层面就强制这个习惯；
2. **质量戳（Good/Bad）进数据模型**——工控软件的区别就在"这个值是读出来的还是猜出来的"；
3. 驱动内部异常不吞：读失败抛给引擎，由引擎决定周期是否继续。

## 线程模型（当前版本）

```
[AcquisitionEngine 后台循环 PeriodicTimer]
        │ ReadAsync（批量）              断线恢复：连续失败达阈值
        ▼                               （ReconnectPolicy：指数退避封顶 15s）
   PointRead 事件（线程池线程）          先断后连驱动，循环重试不弃疗；
        │ SynchronizationContext.Post   失败周期把全部点位按 Bad 质量发布
        ▼                               （读不到是信息，数值冻结是假象）
[UI 线程] 更新 ObservableCollection → DataGrid 刷新
        └→ MainViewModel.PointUpdated 再发布 → 实时曲线页（第二个消费者）
                                            → 报警页（第三个消费者，AlarmEngine 纯逻辑状态机）
                                            → 历史落库（无锁队列 + 后台每 2s 批量事务写 SQLite，
                                              UI 线程永不碰磁盘；报警生命周期事件同路入库）
                                            → OPC UA 北向（DeviceHub.Northbound：点位动态建节点，
                                              值+质量戳刷新——我们是被订阅的服务器）
```

采集引擎状态机：`Collecting ⇄ Reconnecting`——进入 Reconnecting 后每次重试发布状态（含序号/退避间隔/最后异常），恢复后的**首次成功读取**才回到 Collecting。

## 演进记录（面试可讲的重构路线）

| 阶段 | 变化 | 理由 |
|---|---|---|
| M0 → M1 | 点位表写死在驱动里 → `appsettings.json` 配置化 | 加设备不改代码 |
| M0 → M1 | ViewModel 手动 new 驱动 → 工厂按配置创建 + Generic Host/DI 组装 | 组装与使用分离 |
| 待做 | PointRead 事件 → Channel 生产者-消费者队列 | 解耦采集与消费速率，支持背压 |
| ✅ M1 | 失败周期静默跳过 → 连续失败阈值 + 指数退避重连，断线周期发布 Bad 质量 | 现场网络抖动是常态；读不到是信息，冻结是假象 |
| ✅ M1 | Modbus 变体：TCP/RTU 共享协议核心（ModbusDriverBase），新增变体只补传输层 | RTU 与 TCP 的差别只在字节怎么搬，协议行为一模一样 |
| ✅ M2 | 历史落库 SQLite（命名占位符参数化 + 后台批量事务）+ 曲线页历史趋势查询 | 内存窗口管实时，SQLite 管长期账本，各司其职 |
| ✅ M2 | 登录会话 + 角色→能力集权限映射（急停/停止永不做门禁） | 业务操作按角色收敛；安全操作不可锁死 |
| ✅ M2 | Excel 导出（IHistoryExporter 抽象 + ClosedXML 实现） | 报表是"读端"，与写入路径解耦；接口留缝可换 NPOI/CSV |
| ✅ M3 | OPC UA Server（DeviceHub.Northbound，点位动态建节点） | 南向北向同一股采集流：加北向不改采集 |
| ✅ M3 | MQTT 发布（嵌入式 Broker + 遗嘱/保留消息 + JSON 载荷） | 北向双通道：订阅模型（OPC UA）与推送模型（MQTT）各就各位 |
| ✅ M6 | 视觉定位器插拔化：IVisionLocator 双实现（OpenCvSharp 轮廓 / Halcon 形状匹配），配置切换 | 算法是可替换件——换引擎不动标定与引导 |
| ⏳ M2 | 采集异常接入报警引擎 | 重连解决"恢复"，报警解决"可知" |
| 待做 | 单活动设备 → 多设备并行采集 | 一台软件管多条产线 |
