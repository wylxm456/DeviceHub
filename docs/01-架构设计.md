# 01 架构设计

## 分层

```
┌─────────────────────────────────┐
│  DeviceHub.App (WPF/MVVM)       │  界面：只依赖 ViewModel，不直接碰协议
├─────────────────────────────────┤
│  DeviceHub.Drivers              │  驱动实现：Simulated → S7 → Modbus → OPC UA
├─────────────────────────────────┤
│  DeviceHub.Core                 │  抽象与模型：IDeviceDriver / 点位 / 采集引擎
└─────────────────────────────────┘
     依赖方向：上层依赖下层，Core 不引用任何上层项目
```

依赖倒置是本项目的主线：**驱动是插件，引擎和界面是宿主**。
新增协议 = 在 Drivers 里新增一个 IDeviceDriver 实现，Core 与 App 零改动。

## 核心抽象：IDeviceDriver

- `ConnectAsync / DisconnectAsync`：连接生命周期
- `ReadAsync(点位表)`：批量读取，返回与请求一一对应的结果，读不到给 Bad 质量
- `WriteAsync(点位, 值)`：下行控制

设计取舍：
1. **批量读而不是单点读**——真实 PLC 通信一次握手读一段寄存器远快于逐点读，接口层面就强制这个习惯；
2. **质量戳（Good/Bad）进数据模型**——工控软件的区别就在"这个值是读出来的还是猜出来的"；
3. 驱动内部异常不吞：读失败抛给引擎，由引擎决定周期是否继续。

## 线程模型（当前版本）

```
[AcquisitionEngine 后台循环 PeriodicTimer]
        │ ReadAsync（批量）
        ▼
   PointRead 事件（线程池线程）
        │ SynchronizationContext.Post
        ▼
[UI 线程] 更新 ObservableCollection → DataGrid 刷新
```

## 演进记录（面试可讲的重构路线）

| 阶段 | 变化 | 理由 |
|---|---|---|
| M0 → M1 | 点位表写死在驱动里 → `appsettings.json` 配置化 | 加设备不改代码 |
| M0 → M1 | ViewModel 手动 new 驱动 → 工厂按配置创建 + Generic Host/DI 组装 | 组装与使用分离 |
| 待做 | PointRead 事件 → Channel 生产者-消费者队列 | 解耦采集与消费速率，支持背压 |
| 待做 | 失败周期静默跳过 → 重连策略 + 报警 | 现场网络抖动是常态 |
| 待做 | 单活动设备 → 多设备并行采集 | 一台软件管多条产线 |
